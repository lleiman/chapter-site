# Leiman Lab: Google Search Console и измерение органического поиска

**Версия:** 05.11.2026 · **Домен:** https://leimanlab.com/ · **Автор:** Лев Лейман

## 1. Подключение Google Search Console

1. Войти в https://search.google.com/search-console/welcome через Google-аккаунт владельца журнала.
2. Если ресурса нет, создать **URL-prefix property**: `https://leimanlab.com/` (протокол HTTPS и слэш обязательны).
3. В разделе Verification выбрать **HTML tag**, скопировать только значение атрибута `content` из `<meta name="google-site-verification" content="...">`.
4. В Railway → проект `leiman-lab-journal` → сервис `journal-web` → Variables задать `GOOGLE_SITE_VERIFICATION=<значение>`. Не помещать токен в GitHub, не присылать коды входа в чат.
5. После redeploy проверить исходный HTML главной страницы: `curl -s https://leimanlab.com/ | grep google-site-verification`.
6. В Search Console нажать Verify. Метатег оставить навсегда: Google периодически перепроверяет владение.
7. В Sitemaps добавить `https://leimanlab.com/sitemap.xml` (или `sitemap.xml`, если UI уже показывает корневой URL).
8. В Indexing → Pages посмотреть, какие URL индексированы, а какие имеют статус `Discovered - currently not indexed`, `Crawled - currently not indexed`, `Duplicate` или `Blocked`. Интерпретировать каждую группу отдельно, не считать все неиндексированные URL ошибкой.

**Почему URL-prefix:** Google разрешает HTML-tag verification для URL-prefix; Domain property охватывает все протоколы и поддомены, но требует DNS-подтверждения. Для журнала после редиректов каноническая версия одна, `https://leimanlab.com/`. Позже при доступе к DNS можно дополнительно завести Domain property.

## 3. Еженедельный SEO-отчёт

Сравнивать последние **28 полных дней** с предыдущими 28 днями после накопления данных. Для нового ресурса выводить «данных пока мало», а не считать отсутствие кликов регрессией.

- **Индексация:** сколько опубликованных канонических URL найдено, сколько индексировано, причины исключений; проверить `/sitemap.xml`.
- **Google Search:** клики, показы, CTR и средняя позиция; отдельно по запросам, страницам и странам; исключить брендовые запросы для анализа самостоятельного спроса.
- **Распределение трафика:** статьи, главная, AI Index; новые запросы, появившиеся после публикаций.
- **Возможности:** страницы с подтверждёнными показами, слабым CTR и достаточно стабильной позицией; предложения заголовков и description с сохранением авторской интонации.
- **Редакционные действия:** фактическая дата изменения заголовка или материала, гипотеза, измеримый ожидаемый эффект, повторная проверка через 2–4 недели.

## 4. Диагностика, а не гадание по общему трафику

- Показов нет и страница не проиндексирована → сначала диагностика Indexing/URL Inspection, а не изменение текста.
- Страница проиндексирована, но показов почти нет → проверьте поисковый спрос и конкурентность темы; это не обязательно техническая неисправность.
- Показы есть, кликов нет → анализировать запросы и сниппет, не делать вывод по маленькой выборке.
- CTR снизился при росте показов → возможно расширение на менее релевантные запросы, не автоматический признак ухудшения.
- Позиции меняются → смотреть тренд по одинаковым запросам, стране и типу поиска, а не сравнивать несопоставимые средние.

## 5. Следующие измерения

1. Сразу после верификации сохранить список индексируемых URL и выгрузить Search Performance по страницам и запросам.
2. Проверить URL Inspection для главной, AI Index и пяти статей; не запрашивать повторную индексацию всех страниц механически.
3. Сохранять еженедельные экспорты с датой и видом поиска.
4. При необходимости подключить GA4 отдельно для источников посещений и действий после перехода. Search Console не измеряет дочитывания, а внутренние просмотры Leiman Lab не равны кликам из Google.
5. На основе первых данных составить редакционный план из конкретных поисковых вопросов. Для Leiman Lab приоритетом остаётся исследовательская достоверность.
